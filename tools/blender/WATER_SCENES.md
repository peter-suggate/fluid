# Live water landscapes

`tokyo-rain`, `alpine-lake-sunrise`, and `atlantic-lighthouse` are interactive presets in **Explore → Water landscapes**. Each runs the existing `uniform-narrow-band-flip` method with authored scene parameters. Their buildings, mountain ridge, vegetation and rocks are Blender-authored static assets loaded through the normal imported-mesh/FVX pipeline. Water is generated by the running solver; no offline water mesh is loaded into these live presets.

The scenes are implemented and can be inspected in the production renderer. **Current captures are not yet photorealistic.** Numeric checks establish valid scene data and real simulation output; visual quality must be assessed separately in the live app. Cycles look-development renders do not establish the quality or performance of the interactive renderer.

The static asset paths differ: Cycles renders the source meshes; the live renderer reconstructs surfaces from FVX signed-distance samples. Optional FVM companions supply image color, roughness and normals on accepted voxel surfaces. They contain attribute mappings and images, without source positions or triangle indices. Assets without a companion retain baked material values. The live renderer does not load original GLB geometry.

## Open and inspect

Run `npm run dev`, open the app's local URL, and select one of the three presets. To set the visual layers explicitly, append a query such as:

```text
?scene=alpine-lake-sunrise&fluidSurface=shaded&fluidParticles=off&waterReflections=screen-space
```

Replace the scene ID with `tokyo-rain` or `atlantic-lighthouse` for the other scenes. Use the ordinary **Shade** surface mode with particles **Off** to inspect the liquid surface, and particle/field displays to inspect the solver.

Open **Layers → Fluid surface → Shade** to expose **Roughness** and **Reflections** in the normal scene view. The same controls remain on the editing strip. The common **Reflections** control offers:

- **Scene** (`waterReflections=screen-space`): traces against visible scene geometry, with an environment fallback and a water-depth/normal-aware reflection filter. Roughness widens the reflection footprint. Off-screen objects and occluded geometry cannot be recovered from a screen-space buffer.
- **World** (`waterReflections=world-space`): keeps screen-space hits and traces missing rays against the full scene's sparse geometry. It compiles on first selection, uses a bounded traversal, and adds two layered optical targets (32 bytes per render pixel). It is one secondary visibility/shading pass, not recursive path tracing. True misses retain the water environment. Fluid-only views have no full-scene provider and retain Scene reflections. Capture it with `--reflections=world-space --screen-reflection-comparison`; the report separately counts recovered hits, sky misses, and exhausted or invalid samples.
- **Sky** (`waterReflections=environment`): uses the environment reflection and avoids the scene-tracing cost.

The optional **World refraction** control (`waterWorldRefraction=1`, default off)
addresses a narrower case: a refracted ray whose water back interface is missing
from the screen. It traces the existing opaque SVO scene and shades the actual
receiver, then checks the resident liquid field along that ray before accepting
its distance for Beer–Lambert absorption. Valid on-screen exits keep their
existing path, and a nearer analytic opaque receiver cannot be overwritten.
Capture an identical frozen off/on pair with `--world-refraction-comparison`;
`--world-refraction` enables it for the primary capture. This control is
independent of Scene/World/Sky reflection selection.

The liquid check has a fixed 128-sample budget and at most half-cell spacing,
with a subcell receiver-contact tolerance. It initializes the same mixed nodal
sampler used by surface extraction; it does not invent an analytic lake or
accept an unverified air path. Leaving storage or liquid, exceeding the budget,
or failing traversal retains the existing bounded fallback. This is sampled
validation of one water-to-opaque interval, not multi-interface path tracing;
off-screen water-to-air-to-object paths remain unsupported. Diagnostic alpha
is positive measured distance for accepted hits, zero for no request, -2 for
traversal/shading failure, -3 for an opaque miss and -4 for an unverified liquid
interval.

The first production attempt (`live-world-optics-v36`) accepted zero hits and
rejected 850,619 intervals, leaving byte-identical off/on PNGs. Its
verification entry omitted initialization of the mixed sampler's private
lattice state. The corrected production entry now passes an actual GPU
regression using resident mixed topology and coarse nodal textures: removing
only the initialization reproduces rejection, while initializing it accepts
the same two-metre path. The corrected v37 primary capture accepts 849,390 opaque hits with a median
2.703125 m liquid path; 217 intervals remain unverified, five rays miss, and
none report World traversal/shading failure. The foreground changes visibly,
but exposes blocky structural-voxel receivers. A later unrelated capture
harness rebuild failed before the frozen off/on pair, so v37 is not a
successful complete comparison run. The remaining receiver reconstruction
gap is under review. v36 is evidence of the failed integration, not evidence
of a working optical improvement; it also predates the f16 direction matching
and nearer-opaque guards.

A bounded trilinear reconstruction was tested for structural World receivers
using the existing packed voxel distance lane. Synthetic GPU tests recovered
a sloped plane and a narrow first cubic crossing while preserving unavailable
data fallbacks. However, the actual v39 diagnostic sampled 663 eligible terrain
rays in smooth mode 3 and refined **zero** of them; another 28 imported
receivers were correctly excluded. There was no visible bed improvement. The
experiment has therefore been removed from production. Its scalar-data
fallback cause remains unresolved. The prototype lives only beside the
read-only `--world-refinement-diagnostics` tool and its tests, allowing evidence
to be inspected without adding speculative production work or changing the
rendered image. The primary function-fitted dual mesh and secondary per-cell
terrain reconstruction remain different, explaining a current fidelity limit.

The completed frozen v38 refraction comparison accepts 850,020 opaque hits,
with 215 unverified intervals, three misses and zero World failures or WebGPU
errors. Its median path remains 2.703125 m. The foreground is visibly different
from refraction-off, but the exposed bed rectangles are a remaining quality
limit. At 2400×1600, its host-fenced medians were 243.2 ms off and 315.0 ms on;
these include the capture's other enabled lighting controls and are not
interactive frame-rate measurements. The option remains off by default.

The shared optical targets now have two layers to stay within the existing
16 sampled-texture binding limit. The two base targets total 32 bytes per
render pixel even with World refraction off (16 bytes more than before).
Selecting either World feature lazily adds another 32 bytes per pixel, retained
until resize or disposal. At 2400×1600 these are 122.88 MB per pair; with World
reflection already selected, toggling refraction adds execution work but no
further texture allocation. These figures exclude all other rendering assets
and driver overhead.

The **Performance → Upscale + present → Render resolution** control now permits up to **200%**. Above 100% it supersamples geometry and reflections; at 200% the final bilinear resolve averages four shaded samples per display pixel. This helps thin foliage and lettering, at roughly four times the pixel work. It remains an explicit quality choice and is capped to device texture limits and an eight-megapixel budget for extra supersampling (existing native targets are preserved). The frame reports the actual rendered resolution. Capture the same setting with `--render-scale=2`, or add `--supersampling-comparison` to capture both 100% and 200% at the same frozen fluid state.

The **Lighting → Cloud coverage** slider edits the shared environment (zero is clear). Its distant directional cloud pattern is used by both the visible sky and reflected sky; it is an analytic approximation, not a live volumetric atmosphere. Authored directional lighting also controls the environment sun, including turning it off.

**Lighting → Visibility source**, **Shadows** and **AO** are available in the normal view rail as well as the editing controls. They use the existing shared settings. `--lighting-comparison` captures shadows-off, AO-off and unoccluded variants at the same frozen simulation state, without changing source geometry or advancing fluid.

**Lighting → Direct light samples** exposes the shared emitter-sample budget up to 32 (default 8). Area lights may use two samples per source. Higher budgets help scenes with many practical lights and increase shading cost; this does not add missing indirect illumination. The capture equivalents are `--light-samples=32 --area-samples=1`.

For lighting diagnosis, `--indirect-lighting` selects the existing cone visibility path with GI and its world cache enabled, bounce/environment/direct strengths of one and additional GI occlusion strength of zero. It is an explicit comparison configuration, not a new scene default or a claim of path-traced lighting parity. `--reflection-diagnostics` saves the production dry-radiance/depth, water positions/normals, reflection radiance/travel, and camera uniforms as raw buffers for reproducible ray analysis.
Use `--visibility=cones` without `--indirect-lighting` to inspect cone visibility
separately from indirect illumination; `raster-ao`, `exact`, and `off` expose the
other existing visibility choices. The report records the selected mode.

All reflection modes use the resolved scene sky. The shaded compositor combines Beer–Lambert transmission and surface reflection with Fresnel weighting; it no longer adds a separate turquoise body tint after that blend. Both water intervals now use exact dielectric reflectance at the water-to-air exit, continuously approaching total internal reflection. The previous binary 88% environment override produced visible bands at the critical-angle boundary and bypassed the absorbing path and entrance weighting. Internal reflected radiance still uses the environment as a bounded approximation; this is not multi-bounce internal path tracing. A dry surface projected ahead of the water exit now counts as contact only within the coarse interface tolerance, or when the refracted ray actually intersects it. Previously an arbitrarily distant foreground occluder could trigger a false solid exit and draw dark seams through a wave. Both peeled water intervals use the same validation. Interface geometry samples outside the capture are now invalid instead of being clamped to border pixels. A lake buffer replay found false offscreen exits with 6–12 m invented thickness and total internal reflection; the production sampling helper has a real GPU regression for those coordinates. Missing exits still use the existing bounded fallback, so this correction does not provide full offscreen refracted visibility.

This control applies to all scenes. No scene-ID branches are needed in the solver or renderer. Lighting, optics, camera positions and asset placement remain normal authored scene data. The application's lighting-grade `exposure` is a linear multiplier, not photographic EV.

For a reproducible capture through the production app renderer:

```sh
node --import tsx tools/capture-forest-waterfall.ts \
  --scene=alpine-lake-sunrise --time=0.5 --width=1200 --height=800 \
  --out=artifacts/water-scenes/alpine-lake-sunrise/live.png
```

Despite its historical filename, this capture tool accepts any registered scene. It uses the registered solver, scene profile, camera, lighting and normal rendering path. The accompanying JSON records completion and renderer state. `--time=0` captures the initial liquid; a positive time establishes that the solver has advanced. Add `--reflection-comparison` to also write a `-sky.png` capture using the common Sky reflection setting at the same paused simulation state.

## Static asset rebuild

The shared baker now minifies image textures to the physical FVX sampling footprint. A triangle UV/world Jacobian selects a conservative isotropic mip level; base color is averaged in linear space, roughness is averaged as data, and tangent normal vectors are filtered before final normalization. This prevents fine photographic texels from aliasing into coarse bright/dark voxel samples. It cannot recover detail below the baked spacing. Existing FVX files require an explicit rebake to use it. The first filtered shoreline bake preserves every stored distance and normal bit; its weighted mean luminance changed by only 0.049%, while extreme bright samples fell sharply.

The baker also orients shading normals using the parity-derived outward
gradient, after applying normal maps. Inward source winding previously survived
into the lighting field even though the distance field reconstructed an outward
surface. At samples effectively on a source face, a bounded parity probe
resolves orientation instead of dividing float32 nearest-point roundoff. The
shoreline repair changes no stored distance or material value: 92,004 shading
normals and 31 near-face geometric normals are corrected. Opposing shading
normals on 11,076 sampled camera-facing triangles fall from 5,067 to zero.
The source authoring script separately fixes component winding, so Cycles and
future exports use consistently outward source surfaces too.

Generated base-color images must encode their linear values as sRGB before
glTF export. `linear_base_color_image` performs this conversion; normal and
roughness data stay linear. Tokyo's procedural images previously wrote linear
values into PNGs that glTF subsequently decoded as sRGB, making them much too
dark. The corrected production images preserve every original GLB geometry
accessor and every baked distance sample. A Blender-to-GLB round-trip fixture
checks optical values after decoding, including values near the transfer knee.


Author/export scripts produce GLBs and editable Blender sources; the shared volume baker produces sparse FVX files and metadata. Run the export for the collection being changed, then its bake and the catalog generator:

```sh
BLENDER='/Applications/Blender 5.2 LTS.app/Contents/MacOS/Blender'
"$BLENDER" -b --python-exit-code 1 --python tools/blender/export-alpine-runtime.py
"$BLENDER" -b --python-exit-code 1 --python tools/blender/bake_mesh_volume.py \
  -- --collection alpine-lake
npm run generate:assets
```

The other exporters are `export-tokyo-rain.py` (collection `tokyo-rain`) and `export-atlantic-lighthouse.py` (collection `atlantic-lighthouse`). The latter reads the authored lighthouse `.blend`; consult `ATLANTIC_LIGHTHOUSE.md` for its source-generation command. `ALPINE_LAKE.md` and `TOKYO_RAIN.md` describe their scene-specific layouts. These static exports intentionally omit water. Preserve source `.blend`, GLB, FVX, manifest and metadata together.

The shared baker orients shading normals against the parity-derived outward
solid gradient after normal-map sampling. Inward source winding must not invert
the optical field of an otherwise correctly signed volume. Near an exact face,
where float32 nearest-point error can make the distance gradient unreliable,
a bounded parity probe resolves the outward side. This changes normal fields,
not distances, occupancy or material colour; already valid shading detail is
preserved. The required unit suite includes closed reversed-winding fixtures,
exact face samples and a translated thin solid.

## Optional offline Cycles look development

The separate Cycles scripts use actual stepped solver geometry for comparison and material/camera work:

```sh
node tools/blender/render-water-scenes.mjs
```

This runs the three simulation/export/render jobs in parallel. Set `BLENDER` or pass `--blender=/absolute/path/to/blender` when using another installation. Other options include `--scene=tokyo-rain`, `--width=1800`, `--height=1200`, `--samples=192`, and `--out=artifacts/water-scenes`. Use one `--scene` when memory is limited. Failures return a nonzero exit code and a log location.

Each output directory contains:

- `water.obj`: production solver contour, in metres and Blender Z-up.
- `water.json`: scene/mesh hashes, solver settings, actual completed time, geometry counts and GPU errors.
- `render.png` and `render.blend`: the offline image and editable Cycles composition.
- `simulation.log` and `render.log`: execution logs.

To export a specific time without rendering:

```sh
node --import tsx tools/blender/export-nbflip-water.ts \
  --scene=atlantic-lighthouse --time=1.4 \
  --out=artifacts/water-scenes/atlantic-lighthouse/water.obj
```

The exporter advances the registered solver with its effective timestep and profile. It extracts the published fine/coarse signed-distance surface using the same window classifier and polygonizer as application water. It refuses empty, non-finite or capacity-truncated meshes. The coordinate rotation `(x,y,z) → (x,-z,y)` preserves triangle winding. Blender may weld coincident vertices for smooth normals; it does not replace the water with an ocean modifier, plane, hand-built wave or generated image.

The default batch look-development times are 0.8 seconds for Tokyo, 0.5 seconds for the lake and 1.4 seconds for the lighthouse; current lighthouse review captures use 1.0 second. Their fluid cell sizes are 6.25 cm, 50 cm and 25 cm respectively. The lake is a finite enclosed tarn; the lighthouse is a finite wave-impact domain. Millimetre airborne rain, secondary foam and volumetric mist are not resolved by these live fluid grids. Offline Cycles atmosphere and aeration treatments are separate visual effects, not evidence of additional live simulation features.

The optional GI comparison is not a recommended default: the current Tokyo capture showed limited improvement at roughly three times its paused host frame cost (340 ms versus 103 ms at 1000×700). These fenced capture measurements include host overhead and are not interactive frame-rate measurements. Increasing render resolution or direct-light samples also has a substantial cost.
Earlier lake cone-visibility captures exposed self-shadow acne where extracted triangle positions did not lie on the sampled zero surface. The shared visibility path now projects those origins back to their own sampled surface before tracing. GPU fixtures preserve real blockers in the same object. This fixes that origin error. A separate publication bug let image normals alter PCSS receiver planes: keeping image detail in the optical normal removes most fine diagonal ridge marks in `live-lighting-v24` versus `live-clusters-v22` (fresh simulations with the same visibility mode, not identical frozen geometry). `tests/image-normal-visibility-gpu.test.ts` executes the production publisher and normal decoder on the GPU, preserving the receiver plane and real nearer blockers while optical detail varies. This is not evidence of a foliage-volume or GI fix. The same fixture also checks that structural voxel triangles preserve their actual plane when smooth boundary normals change; its live verification follows the v25 shadow comparison.

## Voxel fidelity boundary

The live imported-object pass rasterizes triangles extracted from FVX; SVO/FVX
still determines all geometry, occupancy, picking and secondary visibility.
Image textures on those voxel surfaces are explicitly permitted. **Lighting →
Image textures** (`svoSurfaceTextures=0` to disable) switches the shared optical
attribute path; it does not switch geometry. Assets without FVM companions use
the existing palette path.

FVM1 binds affine UV maps and unperturbed base normals to the exact FVX brick
payload by SHA256. A separate hash verifies the complete companion. Images are
stored with linear-filtered mipmaps in one GPU texture array. Color is sRGB;
roughness is linear alpha; mapped normal components are encoded so the same
sRGB texture format decodes them into linear data. Periodic sampling and
explicit mip levels also work in World reflection compute shaders. The atlas
checks device limits and a 256 MiB budget, reporting an error if exceeded.
Published companions cover the existing 1.25 m mountain ridge and the lighthouse rock, preserving every geometry sample. `--texture-comparison` captures image and voxel-material
modes at an identical frozen water state.

Direct source-triangle primary rendering remains excluded. Blender meshes are
authoring and offline comparison inputs. Current image footprints approximate
camera pixel width; grazing and secondary-ray filtering remain quality limits,
as do voxel silhouettes. Eight-corner material weights blend optical values continuously; each material selects a local affine UV chart without interpolating coordinates across chart seams. World hits from merged structural voxels can lack an imported-asset owner; those hits retain palette attributes because they cannot reliably recover an FVM mapping.

## Review staged voxel bakes

`preload-asset-variants.ts` substitutes staged FVX files only in the capture
process, before the ordinary asset registry snapshots its headers. This allows
resolution and solid-union comparisons without publishing an experiment to the
app. The JSON manifest contains `{ "id": "registered-asset-id", "volume":
"relative/path/to/staged.fvx.gz" }` entries; paths are relative to that manifest.

```sh
FLUID_ASSET_VARIANTS=/absolute/path/to/variants.json \
WEBGPU_NODE_MODULE="$PWD/node_modules/webgpu/index.js" \
node --import tsx --import ./tools/blender/preload-asset-variants.ts \
  tools/capture-forest-waterfall.ts --scene=alpine-lake-sunrise --time=.5 \
  --width=1200 --height=800 --render-scale=1 --supersampling-comparison \
  --reflections=world-space --visibility=raster-ao --out=artifacts/staged-review.png
```

The report records original and staged headers plus the complete uncompressed
FVX hash. The production loader, decoder, scene construction, solver and renderer
still run. For assets with an FVM companion, its geometry hash must also match
the staged FVX. `--lighting-comparison` separately records no-AO, no-shadow and
unoccluded views of the same frozen fluid state. Neither option changes app
defaults.

`--sun-softness-comparison` records the existing Sun softness control at `0.01`
radians against the selected baseline (`--shadow-aperture`, normally `0.065`).
Both are full angular diameters. The lake's Cycles diagnostic now defaults to
the same `0.065` radians; its earlier `0.009250245` reference had sharper shadows.
Neither comparison changes the source assets or simulates another water frame.
`--shadow-diagnostics` additionally reads production receiver normals and shadow
depth for a bounded diagnostic region; it does not alter the rendered image.

## Validation

```sh
npm run check:types
npm run test:unit
```

Scene tests check document serialization, physical basin/collision contracts, registered narrow-band FLIP profiles, valid scenery graphs and the single terrain-shell requirement. Asset validation checks the registered baked headers. Mesh-export tests check units, axis rotation, winding and rejection of invalid geometry. Real exports and live captures additionally record GPU execution and publication state. Inspect the live images after these checks; passing tests alone is not a photorealism criterion.
