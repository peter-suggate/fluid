# FVM1 surface material companion

FVM1 adds optional optical detail to an existing FVX1 sampled solid. Runtime visibility, depth, silhouettes, water interaction and ray intersections continue to use voxel geometry. No source vertices, indices or triangle intersection data are present. Source GLB files are read only by the offline baker.

`bake_surface_mapping.py --collection COLLECTION --asset ASSET --output-dir DIR` reads the published FVX and its unchanged source GLB. It writes an FVM gzip, JSON header and descriptor. The optional FVX header property is `surfaceMapping: {url, sha256}`. SHA-256 covers **uncompressed complete FVM bytes** so HTTP content decoding does not change identity. The FVM header separately hashes the FVX brick payload, excluding its mutable header, avoiding a hash cycle.

Binary layout is four ASCII bytes `FVM1`, little-endian uint32 JSON byte length, UTF-8 JSON padded with spaces to four bytes (padding included in the length), then payload. All payload offsets are relative to its start. The header contains version, asset, sourceSha256, fvxPayloadSha256, origin, dimensions, cellSize, brickCount, brickCells=8, nodeStrideBytes=8, mappingStrideBytes=64, mappingCount, mappingByteOffset, nodeByteOffset, textureByteOffset, textureWidth, textureHeight, textureLayerCount, mipLevelCount, textureFormat=`rgba8unorm-srgb`, textureLayout=`layer-major-mip-major`, materials, and normal encoding/provenance notes.

Each mapping has 16 little-endian words. Words 0–3 and 4–7 are float32 affine U and V rows, evaluated against `(sourcePosition.xyz,1)`. Source position uses the same absolute Y-up coordinates as the FVX origin. Words 8–10 are float32 tangent xyz, word 11 is float32 handedness ±1, word 12 is uint32 material descriptor index, and 13–15 are reserved zero. Mapping zero is the invalid sentinel. Select one mapping among the surrounding valid voxel nodes; never average mappings or UVs across charts. Tangents must be projected against the interpolated base normal and normalized before normal-map application.

Node records follow exactly the associated FVX brick order, and x-fastest 9×9×9 node order within each brick. Each record stores uint32 mapping ID and uint32 oct16×2 unperturbed outward base normal. Identical shared nodes have identical records. Only corners of actual sign-changing FVX cells need records; non-surface records are zero and require the existing sampled-material fallback. A companion mismatch must fail closed rather than attach coordinates to different geometry.

Each material descriptor has name, baseColorFactor[3], roughnessFactor, metallicFactor, colorRoughnessLayer, normalLayer, and normalStrength. Layer `0xffffffff` means absent and uses constant factors. The initial exporter supports TEXCOORD_0 and repeat wrapping; unsupported transformations or addressing fail explicitly. Metallic texture variation is not part of this initial ABI; metallicFactor remains the source constant.

Texture bytes are layer-major, then mip-major from full size through 1×1, tightly packed RGBA8. Dimensions are powers of two; the initial ridge uses 2048². Each image row uses Blender UV's bottom-row-first order, matching the offline imported UVs. Color-layer RGB is sRGB-encoded linear reflectance; alpha is linear roughness. Normal-layer RGB is **explicitly sRGB encoded** after unit source normals are mapped from [-1,1] to [0,1]. Thus a single sRGB texture array decodes both kinds before filtering. Normal mips average unit vectors without renormalizing between levels; the shader decodes to [-1,1] and normalizes after texture filtering. Normal alpha is unused. Color/roughness factors and normalStrength are applied at shading time.

Fixtures in `test_surface_mapping.py` verify affine projection under translations and normal offsets, separate UV charts, degenerate mappings, exact linear checker means, and signed normal means through the sRGB array representation. Actual live captures remain necessary to verify the complete GPU integration.

The current companion exporter requires the default `even-odd` FVX solid rule. It rejects `component-union` volumes explicitly until its mapping orientation and material selection share that component-level solid classifier. This restriction does not affect palette-only foliage volumes.
