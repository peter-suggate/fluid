# Effective source settings versus NB-FLIP implementation

Pinned implementation: `b43993d775a0f9e3a9e32611f26936f2528fac37`. The machine-readable [40-material matrix](wetcloth-effective-material-settings-2026-11-06.json) covers all 36 released water inputs. These are audit findings, not reproduction certificates.

| Setting | Actual source behavior and evidence | Current disposition |
|---|---|---|
| `elastoFlipCoeff`, `elastoFlipAsymCoeff` | `TwoDScene.cpp7077`: filters the symmetric and antisymmetric parts of the solid APIC affine matrix independently. It is not a PIC/FLIP velocity blend. | Solid mechanics is Lagrangian, with no solid APIC matrix; these discretization filters have no literal counterpart. Preserve provenance and validate resulting dissipation, rather than multiply material stiffness. |
| `elastoAdvectCoeff` | `TwoDScene.cpp7075`: multiplies the grid-interpolated solid velocity each substep. Released explicit values .99–.9996 cause timestep-dependent numerical damping. | Not a material viscosity. Current Lagrangian mechanics does not apply this grid-transfer damping. An intentional solver difference requiring motion/energy validation. |
| `flipCoeff`, `apic=1` | `TwoDScene.cpp7016–7018`: liquid velocity is grid interpolation; coefficient scales its APIC affine matrix. | Actual production narrowband FLIP replaces this APIC transfer. Copying the number into a FLIP blend would be semantically wrong. |
| `kernelorder`, bucket `numcells`, particle sampling/correction/split/merge | Source MPM/APIC allocation, interpolation and particle regularization. | Native NB-FLIP uses its real staggered-grid ownership and narrow-band particles. No second MPM liquid solver is introduced. Original h/dt and source geometry remain physical reference inputs. |
| `viscosity`, `computeViscosity` | Parser defaults free-fluid viscosity solve off; the same viscosity still enters pore drag and manifold flow. None of the 36 water XMLs enables `computeViscosity`. | Corrected builder maps computeViscosity to free-fluid viscosity independently. All36 released water inputs set native bulk viscosity to zero; pore viscosity is preserved. Regression added. |
| `surfTension`, `surfTensionCoeff` | Parser defaults free-surface tension off, independently from capillary/cohesive gamma. Only `simple_surf_tension` and `double_surf_tension` enable it. | Corrected builder: native free-surface gamma zero unless enabled; cloth gamma unchanged, including the 90° paper variant. Regression added. |
| `accumulateWithViscous`, `accumulateViscousOnlyForBendingModes` | `StrandForce.cpp259–270`, `ThinShellForce.cpp128–143`: disable all viscous terms, or exclude membrane/stretch only. | Corrected explicit per-mode material mapping; mechanics owner updates CPU/GPU force paths. |
| Solid `viscosity` | `ElasticParameters.h81–98`: stretching/bending use 3η, torsion uses η. Shell tensor retains the elastic Poisson ratio. | Corrected relaxation times: 3η/E for membrane/stretch/bend, η/G for twist, gated above. Previous blanket η/E was wrong. |
| `radius`, `biradius` | Parser defaults each independently to .018 cm. Explicit radius never changes omitted biradius. Shell thickness is their sum; rod area πab. | Corrected source metadata and thickness; anisotropic mechanics and shared ellipse render/contact/edit implementation in progress. Towel radii165/180µm; thickness345µm. |
| `stretchingMultiplier` | Scales elastic and viscous rod stretching. All released inputs omit it, effective1. | Existing unscaled law matches released value; no extra material tuning required. |
| `baseRotation`, `straightHairs` | All40 materials explicitly use baseRotation0; straightHairs omitted/default1. | Source rest-frame orientation must still be reproduced for elliptical material axes. No claim that arbitrary rotation is supported. |
| Material `restVolumeFraction` | Omitted in all40 materials; inherits liquid fraction. The two ring inputs retain their separately authored/default particle vf under `initNonuniformFraction`. | Preserve effective source fraction; raw uniform ring remains vf1/pore0. Exploratory .4 variant is explicitly separate. |
| `frictionAngle`, `friction_angle`, `collisionMultiplier` | Parser reads only camelCase angle, derives α and β=tanθ. `TwoDScene.cpp5226–5334` uses them in Gauss normal/shear return mapping for MPM friction/sliding; collision multiplier scales the normal/shear stress (`1515`, `1559`). | Exact CCD/contact replaces this MPM contact discretization. β provides Coulomb friction, but hard nonpenetration does not reproduce source compliance/return mapping. Do not label collisionMultiplier silently matched. Legacy snake_case is ignored by original parser. |
| `useLevelSetForce` | Adds grid-sampled penalty force at .25h offset with default modulus6.6e6CGS; disabled in11 fixtures including towel and pore tests. | Exact shared-surface CCD replaces source penalty collision. Finite source contact compliance is an explicit method difference, not missing surface geometry. |
| `attachMultiplier`, `fixed` | Finite source attachment forces, not eliminated soft DOFs. | Corrected finite springs and script targets; old hard-pin receipts superseded. |
| `postProjectFixed` | Omitted/defaultfalse in every released input. | No post-solve hard projection should be introduced for source soft vertices. |
| `useApproxJacobian`, `useTournierJacobian` | Omitted; parser defaultsfalse/true, but `ElasticParameters` constructor hardcodestrue/false. | Effective numerical Hessian choice differs from exact-energy nonlinear solve. Residual/energy convergence is the relevant validation, not parser defaults alone. |
| `dragByFutureSolid` | Enabled only pore-test-ft-high and pore-test-low. `LinearizedImplicitEuler.cpp2448` selects post-solid-solve drag versus simultaneous local pressure/drag algebra. | Source coupling-split variant; not yet independently mapped. New force predictor must disclose this difference. |
| `manifoldsubsteps`, source nonlinear drag floor | Source manifold predictor uses outer step plus explicit substeps; nonlinear floor is numerically CGS-dependent. | Mapped substeps and explicit source-only1cm³ reference volume for the floor. |

The released OpenGL yarn preview uses fixed-width line segments (`TwoDSceneRenderer.cpp139–176`); its swept-edge call is commented. It therefore defines no volumetric cap law. Our shared segment-plus-ellipsoid endpoint closure uses axial radius √(ab), explicitly as a collision/render/edit adaptation, not a recovered paper geometry claim.
