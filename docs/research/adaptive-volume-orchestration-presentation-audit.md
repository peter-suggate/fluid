# Adaptive-volume orchestration, activity, and presentation audit

This audit describes the working-tree production GPU method, `adaptive-volume`, on the mini32 scene. Source-content fingerprint at inspection: `1c15404b3310450f9570dea6d730eba5319f7eb2ee50a6d6c78a108c3eedefc8` (1,276 source inputs). It separates source observations from proposed changes. The separate `adaptive-mass` fork and CPU `advance-slice` solver are not evidence of production GPU execution.

## Scene and execution boundary

`createMinimalPowerDamBreak32Scene` halves the base scene's 0.05 m finest cell size, retaining a 0.8 m cubical closed free-slip tank, no rigid bodies, no inflow, zero surface tension, and 1/30 s authored step. The resulting finest lattice is 32³. B8 corresponds to 4³ logical brick coordinates in the authored domain; it does not mean 64 active physical leaves, nor the older B16 eight-brick configuration. Macro leaves, omitted air, and mixed accepted rungs determine actual work. See [scene construction](/Users/petersuggate/code/me/fluid/lib/core/scenes.ts:864) and [mini32 variant](/Users/petersuggate/code/me/fluid/lib/core/scenes.ts:970).

CPU resolution of the current balanced defaults gives B8/P8, coarse-first, macro span `auto`, topology cadence 1, preparation budget 64, RDF presentation, column-height policy `auto`, 128 pressure iterations maximum, tolerance 1e-6, and gamma diffusion/sharpening off. The common-height CG implementation has a separate compile-time `false` gate, so its 64 iterations must not appear in this scene's cost estimate. [Defaults authority](/Users/petersuggate/code/me/fluid/lib/harness/sparse-cm12-dawn-defaults.ts:1), [height gate](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/sparse-cm12-height-reconstruction.wgsl.ts:8).

The actual host order is extension → face prediction → forces → pressure topology/RHS/solve/projection → geometric volume transport → optional markers → scalar publication → activity → resolution planning → candidate transfer → post-topology mask → presentation. The registry retains gamma diffusion, sharpening, and density-capacity-repair names, but the current geometric encoder does not invoke those stage bodies. Reading the registry alone gives the wrong order and obsolete work. [Encoder](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.ts:6706), [transport continuation](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.ts:7295).

## Host control and measurement

The solver submits transport in chunks of 32 packets and asynchronously maps progress before resuming the next chunk. It publishes the physical clock only at complete-frame publication. Transport timestamps span submission gaps, so they measure transport latency, including host continuation waits; they do not establish GPU occupancy. A combined optimization must measure command encoding, device kernel intervals, map/wait time, complete-frame wall time, and topology admission separately. [Chunk configuration](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-adaptive-mass-solver.ts:1558), [continuation loop](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-adaptive-mass-solver.ts:1611).

Pressure iteration feedback uses three four-byte readback buffers and limits the next encoded ceiling using a completed receipt. Failure receipts are also read at completion. Neither is a topology compiler. Combining small control receipts in one staging allocation may reduce mapping overhead, but transport's mid-frame receipt and pressure/failure's final-frame receipts have different dependency boundaries. They cannot simply be read at one time without changing progress semantics. [Receipt allocation](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-adaptive-mass-solver.ts:1521), [final submission](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-adaptive-mass-solver.ts:1573).

Backing-generation preparation is separate asynchronous work, guarded by frame completion, pending work, refusal state, and admission cadence. A pressure/topology GPU timestamp does not capture this entire path. Record candidate planning, CPU geometry construction, transfer preparation, uploads, shader module creation, pipeline creation, and admission wait individually. [Scheduling](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-adaptive-mass-solver.ts:1132).

Every stage invocation also closes the previous pass and snapshots a four-byte failure flag from the topology arena into parameters. These are real command seams even when the stage's numerical work exits early. Preserve halt-before-consumer semantics when changing their implementation. Instrumented substage closers can introduce additional pass boundaries; compare instrumented and uninstrumented complete-frame timing rather than assuming timestamp collection is free. [Stage wrapper](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.ts:6665), [failure snapshot](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.ts:7657).

## Scalar publication

After geometric transport, the host publishes final scalar masks in three dispatches, publishes the scalar output authority, then refreshes and extends the interface over accepted cells. This is a full geometry-value producer even though some mask consumers are incremental. [Scalar publication](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.ts:7047).

Later, presentation again refreshes the published interface and extends it, then publishes RDF values and gradients. This is a reuse opportunity only when the exact scalar bank/version, topology, geometry, and reconstruction policy match. Candidate transfer between the two stages can change cells and field values. A shared geometry-value cache should be keyed by those inputs; after any topology update, fully rebuild its support representation and recompute its values. On an unchanged topology and unchanged final scalar version, alias the already-produced values and run only missing derived products. Never call the earlier geometry automatically valid after remap. [Presentation cache rebuild](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.ts:7708).

## Activity measurement and frontier classification

The stage encodes mask publication, the brick census, history aging, census finalization, and optional sparse-world allocation/synthesis. `measureBrickActivity` launches one 64-lane group per activity brick capacity; a uniform dirty/invalid predicate can exit it. Within a live group, lanes enumerate the accepted rung contiguously with a 64-cell stride. Each cell then walks incidence → row acceptance → row metadata/geometry → signed terms → opposing cells. Field reads are repeated gathers, while the outer cell reads are contiguous. [Dispatch sequence](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.ts:7067), [kernel](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.wgsl.ts:6901).

This gather computes several useful facts together: isovalue crossings, deformation, exposed sides, thin-fluid support, boundary liquid faces, transport extrema, predicted motion, and swept support. Preserve that coalescing. The redundancy is primarily address/acceptance/geometry reconstruction, plus repeated evaluation of pure per-cell geometry inside the row loop. Replace it with the shared compiled signed incidence and physical face view, retaining dynamic openness, density, and velocity. Load the cell's capacity/width/center once; cache row aperture/area/distance once per row visit. Preserve fixed-point moment reductions and float maximum semantics.

The current frontier classifier already reduces 26-neighbour support once per leaf and publishes compact accepted-liquid and presentation-support bits. It would be incorrect to propose introducing that cache as new work. Its neighbour ownership still comes from world lookup; supply the shared compiled neighbour directory. [Existing reduction](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.wgsl.ts:6772).

A full-census design can remove mask rebuilding and history invalidation machinery used only to avoid census work. It must retain actual temporal history and the same refinement policy. History aging can be folded into the owner group's census output when it reads the preceding history and writes one next version. Neighbour support reduction must follow completion of all contributing brick censuses. It cannot be fused into that same dispatch using a workgroup barrier.

Activity and final scalar facts could share per-cell loads only after checking momentum versions: activity uses projected destination cell/face velocities and final density. Surface proofs use a different virtual restricted field and occur after publication. They should consume common compiled addresses, not be treated as duplicate arithmetic.

Curvature is another topology compilation opportunity: `coarseFirstNormal` resolves seven probe owners to choose a common sampling width, then performs six virtual-volume density restrictions. The direct-contained and native overlap paths already avoid finest-voxel quadrature, but repeat ownership, bounds, and overlap decomposition on each call. Compile the common width and ordered donor/weight schedules for fixed cell-centred probes; retain density and cut-solid eligibility as dynamic inputs. [Curvature sampling](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/features/adaptivity/coarse-first.wgsl.ts:103).

## Presentation planning and sample execution

The ordinary presentation tail allocates pages, sorts the directory, then encodes ten frame-plan/packet preparation dispatches, four RDF interface dispatches, copies two indirect-argument regions, and encodes six execution/verification/proof dispatches. It then retires pages, compacts the directory, commits frame control, and snapshots next-frame indirect counts. These are statically counted call sites on the ordinary RDF branch, not measured launch counts or nonempty-work counts. [Tail](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.ts:7247), [plan and execution](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.ts:7662).

Frame-plan initialization writes per-brick and per-tile metadata at full leaf capacity. Population stamps masks, closure resolves masks, sealing checks them, packet construction repacks presentation masks, and execution checks them again. The source comments state several non-presentation stages have not adopted FPL scheduling, yet they still receive global coverage bookkeeping. A mini32 full-publication path can directly enumerate the compiled accepted page descriptors, with compact version/fault/coverage receipts. It must retain all-air retirement publication and camera-independent proof coverage. [Frame-plan initialization](/Users/petersuggate/code/me/fluid/lib/core/sparse-cm12-frame-plan.wgsl.ts:248), [population](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.wgsl.ts:10434), [packet builder](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/sparse-cm12-frame-plan-presentation.wgsl.ts:183).

There is also intra-dispatch repeated work: `populateSparseCM12PresentationFramePlan` calls `geometricPresentationDependencyDirty(brick)` from every tile lane. On B8 there are eight tile lanes. The predicate may walk a shell of logical coordinates and read neighbour activity, although the answer is brick-wide. If that scheduling remains, compute it once per group and broadcast. The more coherent nonincremental design removes this dirty-shell query and publishes all accepted pages. [Predicate and caller](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.wgsl.ts:10415).

The sample executor already stages 27 TEI neighbour leaf descriptors in workgroup memory, computes direct local cell indices, and uses native overlap integration for restriction. It has a native-density scratch cache and an RDF vertex cache. These are existing coalescing wins, not missing features. However, page origin/scale/valid extent, neighbour IDs, fixed sample ownership, and restriction overlap addresses are recalculated from metadata each publication. Compile those schedules once per topology/page-layout revision and retain field values as dynamic inputs. [TEI staging and ownership](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.wgsl.ts:2518), [restriction](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.wgsl.ts:2582), [page preparation](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.wgsl.ts:10667).

The world directory must remain sparse and signed-coordinate capable. Do not replace it globally with a 32³ or bounding-box-sized dense representation just because the reference scene fits one. Within a resident leaf, arithmetic indices and a compiled local neighbourhood are appropriate. Arbitrary remote trajectory lookups need the sparse global fallback.

Page sample writes are contiguous within 4³ tiles. Candidate pages and accepted pages occupy separate regions. `execute` computes candidate samples; `commit` copies accepted samples in a later dispatch; verification and global finalization follow. Directly overwriting accepted samples would destroy rollback on a later fault. A future whole-output-bank swap may remove that copy if the renderer, metadata, retirement handling, and failure protocol all adopt the same publication boundary. This is an architectural change, not a safe local deletion. [Sample and candidate storage](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.wgsl.ts:10795), [commit](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/sparse-cm12-frame-plan-presentation.wgsl.ts:413).

## Surface representability proof

The proof uses one group per leaf, rejects ineligible leaves, stages the same topology, fills a virtual restricted-density lattice, compares accepted and proposed surfaces, reduces normal extrema, and publishes a next-rung certificate. It reuses committed page geometry for accepted samples where possible. The proposed-rung samples differ from current-page samples, so sharing all numeric values would be wrong. Share topology support and overlap schedules; share restricted values only for identical queries at identical scalar versions. [Proof](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.wgsl.ts:11035).

Keep this proof independent of visible renderer pages. It affects adaptive topology correctness; deleting it as presentation overhead would alter physics resolution decisions. A full-publication execution model should still evaluate the full eligible accepted-leaf census.

## Directory lifecycle

Page-directory sorting already touches only newly appended pages; do not count it as a full sort on unchanged frames. Compaction, in contrast, scans the resident directory and invokes world-bound recomputation each presentation tail. These are layout/lifecycle products. Fully regenerate them at topology/page-membership updates, with explicit handling of retirement after all-air publication; reuse them while membership is unchanged. That is whole-generation rebuilding, not per-page patch maintenance. [Sort](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.ts:659), [retirement and compaction](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.ts:682).

## Fusion constraints

Owner-local initialization, calculation, and local receipt reduction can be coalesced using workgroup scratch where ownership is exclusive. Global reductions, neighbour-produced data, pressure iterations, limiter iterations, and all-or-nothing publication require explicit dependency boundaries. WGSL barriers synchronize within a workgroup; they do not provide a grid-wide rendezvous. [W3C, WebGPU Shading Language, synchronization builtins](https://www.w3.org/TR/WGSL/#synchronization-builtin-functions).

Writing indirect arguments in a dedicated producer dispatch can reduce copy/pass seams, but the consumer must not simultaneously bind that argument buffer for writable storage. Validate actual bind groups and WebGPU usage scopes before adopting a same-pass schedule. [WebGPU specification, resource usages](https://gpuweb.github.io/gpuweb/#resource-usages).
