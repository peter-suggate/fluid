# Adaptive-volume geometric transport audit

This audit covers the working-tree production geometric scalar-volume path used by `adaptive-volume`: interface reconstruction, physical subface compilation, CFL planning, low-order limiting, FCT, commit, continuation, source and moving-solid helpers, topology remap, and volume QA. It treats mini32 as the target workload. It does not use the separate `adaptive-mass` implementation as evidence for the live path.

The central finding is specific: the solver already compiles the accepted row graph into physical subfaces plus a cell-to-subface CSR and reuses both throughout every transport microstep. The missing lifetime is topology lifetime. Those topology-invariant products are rebuilt inside every outer transport call. Moving that existing compilation to an all-or-nothing, generation-swapped topology compiler removes repeated graph discovery. It does not by itself remove the likely dominant transport work: every microstep reconstructs PLIC geometry and a historically long dense low-flux limiter loop repeatedly scans the same cell CSR.

## What is already compiled

The physical-subface representation is real, not a proposed feature. `GV_ROWS` maps each accepted row to a contiguous subface range; `GV_META` stores two endpoint cells, source row and static area; `GV_CELL_FACES` plus `GV_CELL_FACE_ENTRIES` form a signed cell CSR. Hot gathers therefore avoid rechecking every unrelated term in a row. [Layout and accessors](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/resident-volume.wgsl.ts:34)

Its lifetime is the problem. `beginGeometricVolumeTransport` clears its allocators and the host immediately recompiles both views every outer transport, even when accepted topology is unchanged. [Begin/compiler sequence](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.ts:7297)

Other structures do not replace it:

- TEI2 is a double-slotted accepted leaf and 4³ packet/spatial-tile execution image. Its records contain cell ranges, origins, scale and packet lane mappings, not physical face endpoints, subface area or cell CSR. [TEI2 layout](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/sparse-cm12-transport-execution-image.ts:7)
- BFA1 is explicitly an immutable all-rung face-address superset. It is useful for stable addressing across rerungs, but it is not the accepted physical subface graph. [BFA1](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/sparse-cm12-brick-tile-face-address-program.ts:1)
- BFP1 is a compact physical row execution order derived from a BTI epoch. It retains row addresses and separates interior/seam execution, but it has no subface endpoint split, area or inverse cell adjacency. No live resident import was found in this audit, so it should be treated as a reusable compiler input or validation model rather than claimed production reuse. [BFP1 contract and record](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/sparse-cm12-brick-tile-face-program.ts:1), [compiler](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/sparse-cm12-brick-tile-face-program.ts:81)

Accepted work-list access is itself indirect. Every invocation resolves a compact accepted index to a template cell or row, and row/term/incidence readers branch between host and dynamic-page storage and use atomic arena loads. That flexibility is appropriate while building a topology generation; it is repeated pointer chasing in transport and reconstruction after the generation is frozen. [Accepted invocation readers](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.wgsl.ts:1392), [row/term/incidence readers](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/sparse-cm12-row-access.wgsl.ts:177)

The shared compiled representation should therefore replace the existing transport-local arrays, not duplicate the complete topology arena. The resident layout deliberately stopped holding a second complete topology graph; broad re-duplication would reverse that memory win. [Resident allocation comment](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.ts:3062)

The current allocation also shows why lifetime and packing matter. Static per-face transport storage is two cell-CSR entries plus four metadata words, or 24 bytes of capacity per possible subface, before row/cell ranges. Dynamic per-face storage is four flux words plus one roundoff word, another 20 bytes. [Host layout](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.ts:3025) The historical mini32 receipt reserved 2,024,352 subfaces but emitted 26,913, so those two capacity-scaled regions represented about 48.6 MB static and 40.5 MB dynamic even before ranges; the receipt is stale and these are layout calculations, not current measured resident bytes. [Historical receipt](/Users/petersuggate/code/me/fluid/artifacts/sparse-cm12-rdf-presentation-performance-final/mini32-rdf.json) Do not blindly double that maximum-capacity allocation. Count first, size or select an inactive compact high-water buffer at a topology boundary, then swap the bind group after certification. Dynamic flux scratch can remain a reusable capacity pool because it is overwritten each microstep.

## Full-generation topology compiler

On every accepted topology change, build a complete inactive `CompiledSimulationTopology` slot and publish it only after certification. This is a full rebuild; no dirty-row list, delta patching, or active-frontier maintenance is needed.

1. Enumerate every accepted physical row and count valid negative/positive physical subfaces. The current `geometricSubface` computes overlap and distance from immutable row/cell geometry and rejects duplicate-cell pairs. [Geometry routine](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/geometric-subfaces.wgsl.ts:35)
2. Exclusive-scan row counts to obtain deterministic row ranges. Emit each `FaceRecord { negativeCell, positiveCell, row, staticArea }` in deterministic order. Prefix offsets avoid the current global atomic allocator. A simple count-then-emit compiler still evaluates pair geometry twice; that is acceptable when paid only on topology updates. Eliminating the second evaluation requires the count pass to retain valid candidate geometry in temporary build scratch, rather than assuming a prefix scan alone preserves it.
3. In a separate certification pass, reproduce the existing total-area and signed per-term marginal checks. Keep its accumulation order fixed. The current compiler checks both total row area and each term coefficient; neither may be replaced by count-only coverage. [Current certification](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/resident-volume.wgsl.ts:379)
4. Count face incidences per accepted cell, exclusive-scan the counts, and emit the signed cell CSR in the exact order expected by transport. Add a reciprocal certificate: every interior face appears once at each valid endpoint, every boundary face once, and all ranges cover the emitted count without overlap.
5. Compile an ordered opposite-neighbour view for interface least squares and support extension from these faces. Store neighbour cell, row/axis and static overlap weight or sufficient geometry to derive it. Retain the exact current ordering if bitwise transport receipts depend on it.
6. Publish generation, accepted cell/row counts, face and adjacency counts, capacities, range-coverage checks, row marginal certificate, reciprocal certificate and a topology fingerprint in a small header. Flip the active slot only when all certificates pass. A failure leaves the prior topology and scalar authority intact.

Static compiled fields are accepted IDs, row ranges, face endpoints, row ID, static subface area, signed CSR entries, neighbour IDs, cell/row geometric address data, and work-group ranges. Evolving fields stay outside the image: volume/density/gamma, pressure, cell and face velocity, source rate, PLIC/RDF values, solid aperture and wall velocity, moving-solid endpoint capacity, limiter factors, fluxes and receipts.

Store topology records as `u32`/packed structures in a read-only storage binding where possible. The current static IDs are bitcast through `f32` state words, and static metadata is interleaved in the same large state allocation as dynamic flux and limiter arrays. [Current mixed layout](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/resident-volume.wgsl.ts:5), [host offsets](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.ts:3025) Separate topology-lifetime data from microstep-lifetime data so transport writes cannot contend with topology headers and so consumers use ordinary storage loads instead of atomic topology accessors.

## Reconstruction and interface cache

For a mixed cell, the baseline least-squares reconstruction walks incidence → row → every opposite-signed term, loads neighbouring activity/open fraction/fill/geometry, calculates overlap and accumulates a 3×3 system. Adaptive extrusion certification and projected-gradient helpers traverse related neighbourhoods again. [Least-squares path](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/geometric-interface-resident.wgsl.ts:379)

Uniform finest cells then try a more expensive path. The extrusion fit resolves a 3×3 stencil and two side cells per sample through `ownerCellAt`; the 3D path resolves a 3³ stencil, can evaluate four seven-cell height columns for each integration axis, and can perform up to eight nonlinear refinements, each scoring analytic plane-box fractions. [Extrusion fit](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/geometric-interface-resident.wgsl.ts:175), [3D fit](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/geometric-interface-resident.wgsl.ts:285)

The compiled opposite-neighbour CSR removes row term scans and repeated host/dynamic topology branches from the baseline least-squares and support-extension paths. For uniform stencils, compile the fixed owner-cell IDs and support flags for the 3³ and long-column probes. Scalar fills still load dynamically. This is worthwhile on mini32 because the method is finest-grid heavy near the dam interface, where the expensive uniform fit is eligible.

The four-float raw PLIC cache already exists and high flux reads it rather than reconstructing per face. [Cache](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/geometric-interface-resident.wgsl.ts:443) Give it explicit keys: topology generation, scalar-bank identity and scalar epoch, solid-geometry revision, and reconstruction-policy version. The first transport microstep may alias the pressure-stage cache only on an exact key match. Later microsteps must reconstruct after the previous global density commit because every plane depends on neighbouring fills.

The support-extension pass is another cell-wide topology walk for invalid open cells. It can read the compiled neighbour view and the completed raw cache, but it remains a second dispatch because all raw neighbour planes must exist first. [Support extension](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/geometric-interface-resident.wgsl.ts:479)

RDF is a derived presentation field, not transport authority. Its value pass enumerates 8 corners × 8 octants, performs sparse owner/connectivity lookup, removes duplicates with an O(n²) scan over up to 64 IDs, and computes PLIC polygon centroids by intersecting, deduplicating and sorting 12 box edges. [Centroid](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/geometric-interface-resident.wgsl.ts:527), [RDF neighbours/value](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/geometric-interface-resident.wgsl.ts:647), [value store](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/geometric-interface-resident.wgsl.ts:722) The gradient pass repeats the same corner/owner/unique enumeration and then reads completed neighbour RDF values. [Gradient](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/geometric-interface-resident.wgsl.ts:783) Compile the unique connected point-neighbour lists once per topology/solid-connectivity generation for presentation reuse, but do not insert RDF work into transport microsteps. The value/gradient boundary remains global.

## Low-order limiter and FCT

For mini32 without moving rigid bodies, the fixed branch matters. Initialization scans every cell face to total incoming low flux and also totals the absolute swept-volume word; the latter value is unused unless solid motion is active. Update then immediately scans the same CSR again. [Initialization](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/geometric-low-flux-limiter.wgsl.ts:60), [fixed update](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/geometric-low-flux-limiter.wgsl.ts:121)

Use a separately compiled fixed-solid pipeline:

- In the first update, use an explicit uniform-factor-one branch for every receiver and calculate incoming, signed delta and outgoing in the same CSR scan; then write the first proposal bank. This preserves the current global fact that all neighbour factors start at one without requiring a separate cross-workgroup initialization barrier. Subsequent passes read the selected completed factor bank and reuse invariant incoming low amount.
- Do not calculate `sweepWeight` on the fixed path.
- Use two dense factor banks. A pass reads all receiver factors from the selected bank and writes all proposals to the other bank. The singleton advances the generation selector only when invalid cells require another pass. This preserves the synchronized Jacobi dependency and removes `commitGeometricLowFluxLimits`, whose fixed branch is only a full accepted-cell copy. It is a dense whole-domain algorithm, not an incremental frontier.
- Preserve the exact per-face multiply, sign and accumulation order. The source comments explain that regrouping can differ by one ulp at capacity. [Roundoff contract](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/geometric-low-flux-limiter.wgsl.ts:123)

Moving-solid transport uses a FISTA-like dual update, old/current/proposed values, closing-component discovery and residual allocation. It is gated by `rigidCoupling` at the host and mini32 does not exercise it. [Host gate](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.ts:7335), [solid inactive implementation](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/geometric-solid-motion.wgsl.ts:11) Keep this path separate until it has its own scene and equivalence measurements; a fixed-branch ping-pong change must not silently rewrite its iteration mathematics.

After low-order convergence, the cell/face/cell FCT passes are each semantically necessary. The safe optimization is reducing record width, address calculation and repeated geometry loads through the shared compiled CSR, and optionally fusing owner-local arithmetic within a stage. Do not fuse across a whole-grid dependency:

- low face publication → cell FCT budgets;
- cell budgets → final face flux;
- final faces → cell validation;
- all-cell validation → scalar authority commit;
- scalar commit → next PLIC reconstruction.

## Host duplication and continuation

`seedGeometricVolumeDestination` is dispatched twice in one frame, before and after preflight topology work. [First and second dispatch](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.ts:6725) The kernel copies density, sets gamma, copies four cell-velocity words and copies four interface-history words per accepted cell. [Kernel](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/resident-volume.wgsl.ts:317) On an unchanged topology the first result is overwritten by the second. Gate the second seed on an admitted topology/scalar-bank change, or delay the single seed until the receiver topology is final. Preserve two seeds only on the transaction path that actually changes receiver identity.

The interface is refreshed and extended before preflight, refreshed again before pressure, and refreshed after transport; later presentation can refresh the published scalar bank again. Cache reuse is legal only under the explicit version key above. If a topology transaction or scalar publication occurred between consumers, rebuild completely. [Early host sequence](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.ts:6725), [post-transport publication](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.ts:7047)

Each encoded transport packet currently contains at least 14 indirect numerical dispatches, two direct one-workgroup publishers, plus two more cell dispatches for moving solids. In the unchunked API the host encodes 512 packets and relies on zero indirect counts after completion. [Packet encoder](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.ts:7317), [unchunked schedule](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.ts:7355) The normal continuation path chunks packets, copies 16 bytes of progress, maps it, and resumes with a new encoder until complete. [Continuation](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.ts:7361)

This makes the reported transport span include queue submission and host mapping latency as well as GPU work. First remove the fixed limiter copy dispatch and repeated topology compilers. Then test a larger fixed maximum schedule in one submission, using indirect zeros after convergence, against watchdog and latency constraints. The direct publisher dispatches still execute even when all following indirect counts are zero, so a 512-packet over-encode is not free. If continuation remains necessary, combine control copies into one mapped staging record per chunk, increase chunk size only from measured queue data, and keep the progress fault semantics.

## Source, remap, solid and QA helpers

Transport-frontier preparation is also a consumer of the same topology. Before physics it gathers material/source and source-velocity bounds, marks cell closure activity, and activates swept support. `activateGeometricSweptCellSupport` walks every material cell's incidence records, reloads row openness/area/axis/source velocity and performs sparse world lookups for swept page boxes. [Host preflight](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.ts:8104), [swept-cell kernel](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/resident-volume.wgsl.ts:683), [support dispatches](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.ts:8142) After projection, the receiver repair scans accepted one-sided rows, tests dynamic density and projected outflow, and records missing sparse neighbours. [Projected receiver kernel](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/resident-volume.wgsl.ts:156) Reuse the compiled cell CSR for per-cell velocity bounds and a compiled boundary-face stream for projected receiver tests. Sparse page allocation and velocity/density tests remain dynamic. If either transaction admits a new accepted topology, finish its conservative state remap, build and certify the complete compiled generation, and only then start transport.

The no-source shader returns constant zero helpers. [No-source implementation](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/geometric-source.wgsl.ts:210) When source support is compiled in, the host always begins source work and clears the source rate for every accepted cell; only the connectivity and publication work is gated on an actual inflow. [Host source sequence](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.ts:6788), [cell clear](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/geometric-source.wgsl.ts:268) For no-inflow mini32, construct a known-zero source generation and skip the full clear on continuing zero-source frames. On the transition from active to inactive, perform one full clear or swap to the zero bank.

With inflow active, the implementation performs 32 rounds of full accepted-row union plus full accepted-cell path compression, then seals rows and scans source bricks. `gsCell`/`gsWeight` repeatedly recompute geometric membership. [Membership](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/geometric-source.wgsl.ts:217), [union/compress](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/geometric-source.wgsl.ts:277) Cache source membership/weight for the frame and drive row connectivity from compiled face endpoints. Source geometry and source configuration remain versioned dynamic inputs; this is not part of the immutable topology image.

Topology edit currently uses delta transfer entry points for cell and face state and builds/replays topology-edit deltas. [Topology transaction](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.ts:7988), [delta transfer/build](/Users/petersuggate/code/me/fluid/lib/methods/adaptive-volume/webgpu-sparse-cm12-resident.ts:8206) The requested design should keep conservative state remap but follow every admitted accepted-topology change with a complete compiled-topology rebuild. Cell remap accumulates or distributes volume, gamma, pressure, velocity and momentum; face remap integrates patch areas and transfers face velocity. These evolving values do not belong in the compiled image.
