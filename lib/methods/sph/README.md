# Traditional SPH

Method id **`particle-sph`** is selectable as **SPH** under **EDIT → Fluid solver**.
[Open the existing mini dam with SPH](http://localhost:3000/scene?scene=minimal-power-dam-break-32&method=particle-sph).
Any existing scene can select the method through its normal URL/picker. Narrow-band FLIP is the default.

This is a standalone, GPU-resident weakly compressible SPH solver. Its basic kernels and explicit force formulation follow [Müller, Charypar and Gross (2003)](https://matthias-research.github.io/pages/publications/sca03.pdf). There is no Poisson solve, particle/grid velocity transfer, affine particle state or iterative density correction.

Each substep builds integer linked neighbor bins, sums poly6 density, evaluates linear equation-of-state pressure `p = c² max(ρ − ρ₀, 0)`, gathers symmetric spiky pressure and viscosity forces, and integrates with symplectic Euler. Approaching-pair artificial viscosity supplies conventional acoustic damping; it is separate from the scene's physical viscosity. Surface tension uses the poly6 color-field gradient and Laplacian. All support radii and derivatives use metres. A fixed normalization removes the initial particle lattice's density quadrature bias; live densities are never renormalized to hide compression.

The scene lattice determines the default particle spacing: **one particle per initially wet cell**. The explicit **8 per cell** sampling option doubles particle resolution in each axis; it is a quality/workload choice. The neighbor directory uses bins as wide as the kernel support (two particle spacings), independently of the rendering lattice. Particle records contain only position/material volume and velocity: 32 bytes each. Density/pressure, force, links and publication are separate buffers. GPU allocation is capped at one million particles and the device's binding limits; larger scenes produce an actionable cell-size error.

The tool rail exposes **stiffness (sound speed)** directly to the right of **SPH**. Editing the number applies live without resetting the run. The three live controls are sound speed (default **20 m/s**), timestep safety (**0.2**) and acoustic damping (**0.2**). Higher sound speed makes the liquid stiffer and requires more substeps. The transport bar's requested dt is respected as an advance horizon; acoustic speed, current particle speed, acceleration, viscosity and capillarity limit the actual GPU substep. Density, force and integration dispatches are batched into one compute pass per reserved substep, with the stability reduction fused into force evaluation, and the reconstructed surface is published once per advance. A bounded submission can cover less than the requested horizon. Capacity exhaustion or invalid particle state latches a failure and retains the prior renderer textures; it does not publish an incomplete frame or clamp velocities to conceal instability.

The solver reads the existing scene's liquid shape, velocity, gravity, density, viscosity, surface tension, container and fixed voxel/terrain solids. Fixed solids use binary cell occupancy and boundary quadrature, with subdivided particle collision checks. Free-slip and no-slip tank modes and open-top outflow are supported. **Rigid bodies and inflows are ignored**, rather than preventing those scenes from opening. Their visible geometry does not imply fluid coupling. Inflow-only scenes begin empty. Live detail, solid editing, fluid injection and particle resampling are not supported; use reset/reconstruction for structural changes.

Rendering uses the standard dense vertex-level-set water interface. A weighted-centroid particle surface is reconstructed once per advance, not every substep. It is an implicit surface estimate, not an exact signed distance or conserved volume. Diagnostics distinguish material volume (including escaped particles), maximum positive density compression and reconstructed volume drift. Free-surface neighbor deficiency is not reported as compression. Expect some surface noise and compressibility; this is an experimental comparison method, not Uniform Geometric parity or a demonstrated realtime performance improvement.

`tests/particle-sph.test.ts` checks registration, controls, material seeding and scene compatibility. `tests/particle-sph-dawn.test.ts` checks GPU density and force sums against independent CPU references, free-fall momentum, rest bounds, dam impact through 0.5 seconds, viscous dissipation, capillary finiteness, voxel barriers, live controls, empty/source/body scenes, outflow accounting, failed-frame publication and the shared renderer. Run `npm run test:dawn -- particle-sph` for diagnosis; final repository gates remain `npm run check:types`, `npm run test:unit` and the full serial `npm run test:dawn`. Browser GPU work must be stopped during Dawn.

Measured cost and the resolution/stiffness tradeoff are recorded in [the SPH verification report](../../../docs/verification/sph-2026-10-07.md). The 32³ label describes the scene/render lattice, not a pressure-step budget.
